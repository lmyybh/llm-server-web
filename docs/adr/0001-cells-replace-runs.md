# 压测层级重构：Cell 取代 Run，Workload 全局化

压测侧原层级为 Model → Deployment → Workload → Run：Workload 混合了负载形状与考核方式（模式+档位），Run 是一次档位扫描的执行记录并保留全部历史。重构后层级为 Model → Deployment → Cell，外加一个全局共享的 Workload 库：Workload 只定义负载形状（合成 tokens 或真实数据集名，内容不可变），Cell 是 (Deployment, Workload) 交叉点上的单点测量（mode + 档位值 + 请求数），只保存最新一次结果，重跑覆盖。

## Considered Options

- **保留 Run 与执行历史**：能看趋势与回归，但历史数据与配置漂移的仲裁成本高，且 v1 没有趋势需求。
- **Benchmark 实体（一次执行扫一条曲线）**：曲线原子自洽，但跨 Deployment 对比要求档位阶梯完全相等——实际中"A 跑 [1,4,16]、B 跑 [1,4,16,64]"的重叠点无法利用，配对规则僵硬。

## Consequences

- 曲线变为读时拼装：同一条曲线的各 Cell 可能执行于不同时间、不同条件，页面上无法看出。接受此代价，换取任意重叠子集可比与单点重跑。
- 可比性判定简化为"引用同一 Workload（按身份）+ 同 mode + 同档位值"；不再校验数据集内容哈希（真实数据集预置且视为不变）。
- 无执行历史：趋势与回归追踪不可做，误触重跑不可恢复。执行快照（Cell 上冻结的上次执行配置）承担配置漂移的提示职责。
- 数据库推倒重建，不写迁移（内部工具，既有数据无保留价值）。
- 巡检侧不受影响，保留 Service → Inspection Run。
