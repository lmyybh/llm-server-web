## 验证记录

后端 33 个测试（18 个纯逻辑 + 15 个接口）+ 前端 3 个。**真实业务负载跑通**：

```
/api/datasets → [{name: "sample", path: "sample-business.jsonl", exists: true}]
run #9  来源=dataset  数据集=sample
  数据集哈希=0df14ed1ee6b9ff5…
  数据指纹  =b92e4ba5853793ed…
  档位 2: 6/6 成功  ttft_p50=204.6ms  e2e_p50=1727.8ms
  finish_reasons={'length': 6}
```

`finish_reasons` 全是 `length` 说明 `ignore_eos` 生效了——**业务负载默认会在模型觉得该停的地方停**，那样每次请求的输出长度都不一样，测量就不可复现。有 `max_tokens` 时补上 `ignore_eos`，让长度由请求说了算。

### 两个哈希，各管一件事

| 值 | 位置 | 作用 |
|---|---|---|
| **数据集哈希** | 签名里每个测量项 | 这次用的是**哪一个**文件（内容级） |
| **数据指纹** | 签名顶层 | 这次用的**全部**数据（各哈希排序后再哈希） |

分开是因为可比性需要一个**单一**的值来比较，而"用了哪一份数据"需要的是明细。用多维哈希列表比较，会让两次用同样数据集但顺序不同的 Run 看起来不同。

### 边界都是显式拒绝

- 一个测量项不能既是合成又是数据集（两者端点都不同）
- 一个测量项不能两者都不是
- 合成测量项必须给输出长度
- 数据集未注册 → 422 并列出已注册的名字
- 数据集文件丢了 → 422 并指出路径
- **数据集在创建任何东西之前解析**，所以一份坏数据集是一次拒绝，而不是一个排完队才失败的 Run

### 业务负载不受生成上限约束

生成上限管的是**合成出来的** token 数。一个真实请求有多长就是多长，拿上限去卡它没有意义。
