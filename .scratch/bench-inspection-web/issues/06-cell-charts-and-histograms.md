# 06: Cell 结果曲线与延迟分布直方图（重构）

**What to build:** Cell 结果的可视化：按 (Workload, mode) 分组的曲线（X=档位）与按 Cell 的直方图。曲线是**读时拼装**——同一曲线的各 Cell 可能跑于不同时间，界面必须让人看见这一点。

**Blocked by:** 05

**Status:** open

- [ ] 曲线按 (Workload, mode) 分组：X 轴为档位值（**对数刻度**），每个指标一张小图（TTFT p99 / TPOT p99 / 吞吐 / 成功率）
- [ ] **每个点标注执行时间**（`last_run_at`）——这是读时拼装曲线的必付代价（ADR-0001），不标注就是在隐藏混血曲线
- [ ] 配置改过未重跑的 Cell 显示"结果来自旧配置"提示（对照执行快照）
- [ ] 按 Cell 展示延迟分布直方图——p99 会掩盖双峰，而 LLM 服务的延迟经常就是双峰的
- [ ] 界面说明计时口径：高并发档位呈现的是**服务时间**，不是用户感知的响应时间
- [ ] **不画任何 SLO 参考线，不做任何 PASS/FAIL 着色**——拐点由人看曲线判断

## 沿用自 Run 实现的教训

- **不引入图表库**：手写 SVG（约 100 行）。"不做 SLO 着色"因此是结构上保证的——组件里根本没有阈值这个概念可传。
- **每个指标一张小图**：单位不同（毫秒、req/s、百分比），共用一个 Y 轴没有一个能读。
- **X 轴标题取决于模式**：`并发` 或 `提供的 QPS` 是不同的实验，共用一个标签会误导。
- **同一指标的直方图分桶边界一旦落库就不能再动**——改边界会让已存直方图失效。
