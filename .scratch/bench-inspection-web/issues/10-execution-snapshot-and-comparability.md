# 10: 执行快照与可比性判定（重构）

**What to build:** Cell 每次执行冻结执行快照；可比性判定简化为"同一 Workload（按身份）+ 同 mode + 同档位值"，对比取交集逐点对齐。

**Blocked by:** 05

**Status:** open

- [ ] 执行快照含：Workload 形状（含数据集名）、mode、level、num_requests、固定值（warmup=5、flush 开、seed）、执行器标识、负载发生器版本
- [ ] Cell 配置（num_requests）修改后未重跑，界面提示"结果来自旧配置"
- [ ] 可比的充要条件：**同 `workload_id` + 同 `(mode, level)`**；档位阶梯不必一致，对比取**交集**
- [ ] **不校验数据集内容哈希**——真实数据集预置且视为不变（ADR-0001）；执行时 sha256 可记入产物供审计，但不参与判定
- [ ] 执行器标识与负载发生器版本被记录但**不作为对比轴**；版本变化时给出提示
- [ ] **跨 Model 的对比在 API 层被拒绝**——差异来自模型本身而非部署方式

## 沿用自 Run 实现的教训

- **"缺字段"被当作一个值，不是"一致"**：没有快照的 Cell 不等于"和另一个配置相同"——缺席本身就是差异。
- **`seed` 不参与比较**：它改变发出去的是哪串随机 token，不改变发送的条件。
