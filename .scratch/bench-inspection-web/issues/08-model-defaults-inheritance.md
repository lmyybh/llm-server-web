# 08: Model 默认值与 Deployment 继承

**What to build:** Model 上有一套显式默认值，新建 Deployment 时继承；在 Deployment 上改参数只影响它自己。

**Blocked by:** 03

**Status:** done

- [x] Model 上可查看与编辑默认值
- [x] 新建 Deployment 时预填 Model 的默认值
- [x] 在 Deployment 上修改参数**不改变** Model 的默认值
- [x] 修改 Model 默认值**不改变**已存在的 Deployment（它们保持创建时的值）
- [x] 任一时刻都能指着某一层说出"这个值是从哪来的"，不出现隐式继承

## 验证记录

后端 12 个测试 + 前端 5 个。三层优先级：**内置默认 → Model 默认 → 调用方传入**，每一层各有一条测试钉住。

**服务端也应用默认值**，不只是在界面预填。界面预填是为了让人看见将要发生什么；服务端应用是为了让跳过预填的调用方也拿到 Model 的默认——两者缺一，默认值就只在某一条路径上生效。

### 两个决定

**身份字段不可设默认值。** `name`、`router_url`、`model_name` 不在可默认的字段里——一个模型没法对"叫什么名字"有合理的默认，硬给一个只会造出没人想要的部署。而且 `ModelDefaults` 用的是 `extra="forbid"` 而不是 pydantic 默认的"忽略多余字段"：静默丢掉调用方给的 `router_url` 默认值，会让人以为它生效了。

**清空 = 缺席，不是 null。** 服务端丢弃值为 `null` 的字段，所以清空一个默认值会**回落到内置默认**，而不是用一个 null 把它遮住。
